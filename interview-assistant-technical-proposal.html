模拟面试助手技术方案

基于 React + Python FastAPI + LangChain + RAG + DeepSeek 的对话式模拟面试系统，采用“应用本机跑，依赖 Docker 跑”的开发模式，优先完成可演示 MVP 闭环。

React 对话式前端 FastAPI 后端 LangChain 应用编排 DeepSeek 模型调用 Qdrant RAG 知识库 PostgreSQL / Redis / MinIO
01 / 产品定位

面向求职者的 AI 模拟面试训练系统

系统通过用户上传的简历、岗位 JD、题库、公司资料和历史回答构建个人知识库，并由 AI 面试官以对话方式持续提问、追问、评分和生成复盘报告。

岗位定制面试专项训练简历深挖系统设计行为面试面试复盘
02 / 开发模式

App 本机跑，依赖 Docker 跑

React、FastAPI、LangChain 直接运行在 Mac 本机，便于热更新、断点调试和快速迭代；PostgreSQL、Redis、Qdrant、MinIO 通过 Docker Compose 启动，保证基础设施稳定一致。

  • 本机：React、FastAPI、LangChain、DeepSeek API 调用逻辑。
  • Docker：PostgreSQL、Redis、Qdrant、MinIO。
  • MVP 可简化：先只启 PostgreSQL + Qdrant，Redis / MinIO 后补。

04 / 总体架构

系统链路

React Web localhost:5173
  │ REST / SSE / WebSocket
  ▼
FastAPI Backend localhost:8000
  ├─ Interview Orchestrator：面试状态机与流程控制
  ├─ LangChain Layer：Prompt / Chain / Retriever / Tool 编排
  ├─ RAG Service：文档召回、Rerank、上下文组装
  ├─ Evaluation Service：单轮评价与整场报告
  └─ DeepSeek Service：OpenAI-compatible 模型调用

Docker Dependencies
  ├─ PostgreSQL localhost:5432：业务数据
  ├─ Redis localhost:6379：缓存、任务状态、限流
  ├─ Qdrant localhost:6333：向量检索
  └─ MinIO localhost:9000：上传文件对象存储
05 / 前端

React 对话式体验

  • 首页：创建面试、历史面试。
  • 资料库：上传简历、JD、题库。
  • 配置页：选择岗位、难度、资料范围。
  • 面试页：聊天窗口、阶段、实时反馈、引用来源。
  • 报告页：总分、分项评分、建议答案、训练计划。
06 / 后端

FastAPI 服务分层

  • API 层：documents、interviews、messages、reports。
  • 服务层：文档解析、RAG、面试编排、评价。
  • Chain 层：提问、追问、评分、报告生成。
  • 数据层：SQLAlchemy + Alembic。
  • 配置层：pydantic-settings 管理环境变量。
07 / AI

LangChain + DeepSeek

  • DeepSeek Chat：常规提问与对话。
  • DeepSeek Reasoner：复杂评价、系统设计追问。
  • Embedding：BGE / Qwen Embedding。
  • Retriever：Qdrant VectorStore。
  • Prompt：严格约束“每次只问一个问题”。
08 / RAG 知识库

资料上传到面试召回

1. 上传：简历、JD、题库、项目说明、公司资料。
2. 解析：PDF / DOCX / Markdown / TXT 转纯文本并清洗。
3. 切分：按语义 chunk，附带 document_type、section、tags 等 metadata。
4. 向量化：调用 embedding 模型写入 Qdrant。
5. 召回：面试时按阶段限定 scope，检索相关 chunk，必要时 rerank。
6. 注入：将高相关知识注入 Prompt，让 DeepSeek 基于真实资料提问和评价。
09 / 面试状态机

流程可控，不让模型自由乱跑

INIT
  → SELF_INTRO
  → RESUME_DEEP_DIVE
  → TECHNICAL_QUESTIONS
  → SYSTEM_DESIGN
  → BEHAVIORAL
  → SUMMARY
  → FINISHED

后端维护阶段、题目数量、难度和 RAG scope。LLM 负责生成内容，不负责决定全部业务流程。

10 / 核心 API

第一版接口

  • POST /api/documents/upload 上传资料。
  • POST /api/interviews 创建面试。
  • POST /api/interviews/{id}/messages 发送回答并流式返回。
  • POST /api/interviews/{id}/finish 结束面试。
  • GET /api/interviews/{id}/report 获取报告。
11 / 多 Agent 执行思路

拆成多个 agent 并行推进

这个项目天然可以拆成多个独立工作流：前端、后端 API、RAG、LangChain、DevOps、测试文档之间边界清晰。建议由一个主控 agent 负责架构约束、接口契约和集成验收，其余 agent 并行实现各自模块。

Agent A：前端

实现 React 页面、对话 UI、SSE 流式渲染、上传组件和报告页。

Agent B：后端 API

实现 FastAPI 路由、数据模型、会话存储、面试状态机。

Agent C：RAG

实现文档解析、chunk、embedding、Qdrant 检索和 metadata 过滤。

Agent D：LangChain

实现提问链、追问链、评价链、报告链和 DeepSeek 适配。

Agent E：DevOps

实现 Docker Compose、环境变量模板、启动脚本和 README。

Agent F：测试验收

实现 API 测试、RAG 检索测试、端到端手工验收清单。

13 / 结论

第一版建议

第一版不要追求复杂功能，先打通 “上传资料 → RAG 检索 → 对话模拟面试 → 单轮评价 → 最终报告” 主链路。开发环境采用 App 本机跑、依赖 Docker 跑，兼顾调试效率和环境稳定性。工程执行上建议多 agent 并行开发，由主控 agent 负责接口契约和集成验收。
